# CyberSentinel AI

> **LLM-Powered Cybersecurity Agent Framework**

CyberSentinel AI is a modular cybersecurity framework that uses **Large Language Models (LLMs)** and **multi-agent workflows** to perform tasks commonly encountered in day-to-day cybersecurity operations.

The framework is built on top of **Microsoft AutoGen** and provides a collection of agents, actions, tools, and predefined scenarios that can be combined and customized for security automation, analysis, investigation, and experimentation.

---

## Overview

Cybersecurity teams perform many repetitive tasks involving analysis, investigation, detection engineering, and security operations.

CyberSentinel AI explores how LLM-powered agents can assist with these workflows through a modular architecture where specialized agents can communicate with each other and use defined actions and tools.

## Key Features

### Modular Design

The framework is composed of individual agents, actions, and tasks that can be combined and customized for different cybersecurity use cases.

This modular approach makes it possible to extend the framework with new agents and workflows as security requirements evolve.

### Automation

LLM-powered agents can assist with repetitive and complex cybersecurity tasks, helping security teams explore automated approaches to analysis and decision support.

### Batteries Included

The project provides predefined agents, workflows, actions, tools, and example scenarios that can be used as a starting point for experimentation.

### Multi-Agent Workflows

Multiple specialized agents can collaborate to complete a cybersecurity task, allowing individual agents to focus on specific responsibilities.

### Extensible Architecture

New agents, actions, tools, and scenarios can be added to extend the framework for additional cybersecurity use cases.

# Getting Started

> [!CAUTION]
> **LLM-generated source code and commands can pose a security risk to your host environment.**
>
> Run this project only inside a **virtual machine, sandbox, or dedicated test environment**. Do not blindly execute commands generated by an LLM.

## Prerequisites

Make sure the following are installed:

- Python 3.9+
- Git
- pip
- Microsoft AutoGen dependencies
- An LLM API provider supported by the project
- VS Code or another Python-compatible IDE

---

## Step 1 — Clone the Repository

```bash
git clone https://github.com/aryamanchaudhary2005/CyberSentinel-AI.git
cd CyberSentinel-AI
```

---

## Step 2 — Create a Virtual Environment

### Windows

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

---

## Step 3 — Install Requirements

Install the required Python packages:

```bash
pip install -r requirements.txt
```

---

## Step 4 — Configure LLM API Information

Create your environment configuration file from the provided template.

### Windows PowerShell

```powershell
Copy-Item .env_template .env
```

### Linux / macOS

```bash
cp .env_template .env
```

Open the `.env` file and configure the required LLM API information and other project parameters.

### Security Notice

**Never commit \*\***`.env`\***\* to GitHub.**

Do not expose:

- API keys
- Access tokens
- Passwords
- Private credentials
- Production secrets

The `.env` file should remain local to your development environment.

# Running the Project

## Hello Agents

Run the basic scenario to verify that the framework is configured correctly:

```bash
python run_agents.py HELLO_AGENTS
```

A successful execution should start an agent conversation and produce a response from the participating agents.

Example:

```text
Starting a new chat....

task_coordinator_agent:
Tell me a cyber security joke

text_analyst_agent:
Why was the computer cold?
It left its Windows open.

TERMINATE
```

If the scenario executes successfully, the basic agent configuration is working.

# Optional HTTP and FTP Servers

The project includes functionality for starting simple HTTP and FTP servers for certain demonstrations and agent interactions.

Start the servers with:

```bash
python run_servers.py
```

> **Security Warning:** Only run these services inside an isolated test environment or virtual machine. Do not expose experimental services to untrusted networks.

# Building Scenarios

Cybersecurity scenarios are defined in:

```text
actions/agent_actions.py
```

Scenarios can be modified or extended by adding new agent actions and workflows.

Once a scenario has been added, execute it using:

```bash
python run_agents.py <scenario-name>
```

For example:

```bash
python run_agents.py HELLO_AGENTS
```

### Scenario Workflow

```text

       ▼

       │
       ▼

       │
       ▼
Execute Agent Workflow
       │
       ▼
Analyze Results
```

# Static Analysis and Code Quality

The project uses `flake8` for static analysis.

The following command can be used to check the codebase:

```bash
flake8 --exclude=.venv --ignore=E501,W503 .
```

### Ignored Rules

**E501** is ignored because agent prompts and action strings can contain long lines.

**W503** is ignored based on the project's formatting preference regarding line breaks before binary operators.

# Security Considerations

LLMs can generate commands, scripts, and security actions that may have unintended consequences.

Before executing an agent-generated action:

1. Review the generated output.
2. Verify the command or code.
3. Use an isolated test environment.
4. Avoid production credentials.
5. Monitor the system being tested.
6. Never test against systems without authorization.

For security research involving potentially destructive operations, use dedicated virtual machines and controlled lab environments.
